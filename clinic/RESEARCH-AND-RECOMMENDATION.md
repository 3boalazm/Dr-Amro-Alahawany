**العيادة:** أ.د. عمرو الأهواني — استشاري جراحات وأمراض الذكورة، كلية الطب جامعة القاهرة
**الفرع:** 26 شارع البطل أحمد عبد العزيز — المهندسين، الجيزة
**التاريخ:** أكتوبر 2026

## ١. الخلاصة التنفيذية

**التوصية:** نبني النظام على **Easy!Appointments** (اللي اندمج في الريبو ده فعلًا) كعمود فقري،
ونضيف فوقه **طبقة واجهة عربية مخصصة** + **واتساب** + **سجل موافقات متوافق مع القانون المصري**.
مش هنشتري منصة SaaS جاهزة.

السبب في سطر واحد: التخصص حساس، والبيانات الصحية في مصر بقت **محمية بقانون بيبدأ تطبيقه فعليًا
من ١ نوفمبر ٢٠٢٦** — يعني بعد أسبوع. أي منصة خارجية هتحتاج ترخيص نقل بيانات خارج مصر، وده تعقيد
مش لازم. الاستضافة الذاتية بتحل المشكلة دي من جذرها وبتوفر ٧٠–٩٠٪ من تكلفة الاشتراكات.

**مؤشر الأرقام:** بدائل السوق المصري بتتراوح بين **٦٩٩ و ٢٬٢٩٩ ج.م/شهر** ([1], [2]).
النظام الذاتي تكلفته الثابتة تقريبًا **خادم ٢٠٠–٤٠٠ ج.م/شهر + رسائل واتساب**، والباقي ملكية كاملة.

## ٢. تشخيص الموقف — إيه اللي العيادة محتاجاه فعلًا

من قراءة الموقع الحالي، فيه ٤ حقائق تحكم أي اختيار:

| الحقيقة | الأثر على التصميم |
| --- | --- |
| **التخصص حساس** (ذكورة، خصوبة، جراحات) | المريض بيهتم بالسرية أكتر من أي حاجة. أي إشعار فيه اسم العيادة على شاشة الهاتف = مشكلة. |
| **الحجز الحالي = مكالمة أو واتساب** | الاستقبال بيشتغل يدوي، ومفيش توزيع ذكي للمواعيد → تكدّس و no-shows. |
| **الجمهور مصري، موبايل أولًا** | عربي RTL، أرقام لاتينية، واتساب هو قناة التأكيد الطبيعية مش الإيميل. |
| **الموقع WordPress** | أي نظام لازم يندمج مع ووردبريس بسهولة (صفحة حجز أو iframe أو API). |

## ٤. ليه مش Vezeeta؟

لأن التخصص ده بالذات، **الظهور في ماركت بليس ضرر مش مكسب**:

- المريض بيدوّر على خصوصية، مش على إعلان.
- المنصة بتتحكم في شكل ظهور الطبيب وسعر الكشف.
- مفيش تحكم في مكان تخزين البيانات الصحية (نقل خارج مصر → يحتاج ترخيص PDPC).
- العمولة على كل مريض جديدة بتاكل من هامش الاستشارة.

البديل الصحيح: **وجود رقمي خاص** على `ahwani.com` نفسه + محتوى توعوي يجلب المريض مباشرة.

## ٥. الميزات المميزة — مرتّبة بالأولوية

### P0 — لا يعمل النظام بدونها

| الميزة | ليه؟ |
| --- | --- |
| **حجز عربي RTL فوري (Real-time)** | المريض بيشوف الأوقات المتاحة فعلًا ويحجز في ٦٠ ثانية |
| **تذكير واتساب** | الواتساب هو أعلى قناة وصول في مصر. بيقلّل الـ no-show بنسبة كبيرة |
| **إلغاء / إعادة جدولة ذاتي برابط** | بيحوّل شغل الاستقبال لمريض، وبيحرّر الموعد الملغي فورًا |
| **سجل موافقة صريح (PDPL)** | نسخة نص + وقت + IP + إمكانية السحب — مطلوب قانونًا للبيانات الصحية |
| **وضع «الإشعارات السرّية»** | رسائل من رقم محايد، بدون اسم العيادة أو التخصص، وبدون تفاصيل طبية |
| **إخفاء الحقول الحساسة** | Easy!Appointments أصلًا بيسمح بتخفيف حقول (العنوان/المدينة) — مفيش داعي نجمع بيانات مش محتاجينها |

### P1 — اللي بيخلّي التجربة «مميزة» فعلًا

| الميزة | ليه؟ |
| --- | --- |
| **عربون مقدم اختياري** | بيقتل الحجوزات الوهمية تمامًا. مناسب لخدمات زي الدوبلكس |
| **قائمة انتظار ذكية** | أول ما موعد يتلغي، بيتبعت إشعار تلقائي لحد في قائمة الانتظار |

| **لوحة تحليل** | نسبة الحضور، الأوقات الأكثر طلبًا، الخدمات الأعلى |

## ٦. ⚠️ الالتزام القانوني — ده مش تفصيلة

قانون حماية البيانات الشخصية المصري **رقم ١٥١ لسنة ٢٠٢٠**، ولائحته التنفيذية صادرة بقرار
رئيس الوزراء **رقم ٨١٦ لسنة ٢٠٢٥** (١ نوفمبر ٢٠٢٥، ونُشرت في الجريدة الرسمية ٢٥ ديسمبر ٢٠٢٥)،
وبدأت **فترة سماح سنة تنتهي ١ نوفمبر ٢٠٢٦** ([3], [4], [5]).

البيانات الصحية تُصنَّف **«بيانات شخصية حساسة»** (المادة ١٢). ومعناها عمليًا:

1. **ترخيص من مركز حماية البيانات الشخصية (PDPC)** قبل جمع/تخزين/معالجة البيانات الحساسة.
2. **موافقة صريحة مكتوبة** (ورقية أو إلكترونية) من صاحب البيانات — الإيماء أو الموافقة الضمنية **غير كافيين**.
3. الموافقة تكون **بالعربية**، منفصلة عن شروط الاستخدام، وبفعل إيجابي واضح.
4. **حق السحب والحذف والتصحيح** — ولازم يكون عندك سجل يثبت ده.
5. **ضوابط أمنية** معتمدة من المركز.
6. **نقل البيانات خارج مصر** يحتاج ترخيص أو تصريح منفصل + موافقة صاحب البيانات ([6]).

**الترجمة العملية للبناء:**

- كل حجز يسجّل: `نص الموافقة + رقم النسخة + التاريخ + IP` ← ده موجود في البروتوتايب.
- لو استضفنا على سيرفر **داخل مصر**، بنستغنى تمامًا عن إجراءات نقل البيانات للخارج.
- الاستضافة الذاتية (بدل SaaS أجنبي) بتقلّل سطح المخاطر بشكل جذري.

> ملاحظة: ده تلخيص هندسي مش استشارة قانونية. يُستحسن مراجعة محامٍ متخصص قبل التشغيل الفعلي،
> خصوصًا بند الترخيص من PDPC.

## ٧. تكلفة رسائل واتساب — بالأرقام

من **١ أكتوبر ٢٠٢٦** تغيّر تسعير Meta ([7], [8]):

- كل رقم بيزنس بياخد **١٠٠٠ رسالة خدمة مجانًا شهريًا**، وبعدها بتتحاسب.
- **قوالب Utility داخل نافذة ٢٤ ساعة بقت مدفوعة** (كانت مجانية).
- رسائل المريض الواردة لك **مجانية دايمًا**.

**تقدير لعيادة بـ ٤٠٠ موعد/شهر** (تأكيد + تذكير ٢٤ ساعة + تذكير ٣ ساعات ≈ ٣ رسائل/حجز ≈ ١٢٠٠ رسالة):

| البند | التقدير |
| --- | --- |
| أول ١٠٠٠ رسالة | مجاني |
| الـ ٢٠٠ الباقية | بسيطة (سعر السوق المصري من أرخص الفئات) |
| **الإجمالي** | **أقل من ٥٠ ج.م/شهر** |

مهما كان الرقم دقيق، هو **مش** اللي هيكسر الميزانية. اللي بيكسرها هو الاشتراكات الشهرية.

## ٨. القرار المعماري

```
┌──────────────────────────────────────────────┐
│  ahwani.com  (WordPress)                     │
│  ← زر "احجز موعدك" يفتح /booking             │
└───────────────────┬──────────────────────────┘
                    │
┌───────────────────▼──────────────────────────┐
│  واجهة الحجز العربية (RTL) — البروتوتايب     │
│  خدمة → يوم/وقت → بيانات → تأكيد             │
└───────────────────┬──────────────────────────┘
                    │  REST (JSON)
┌───────────────────▼──────────────────────────┐
│  Easy!Appointments (PHP 8.2 + MySQL/MariaDB) │
│  • جدولة وساعات عمل • إلغاء/تأجيل            │
│  • سجل موافقات • Webhooks                    │
└───────┬───────────────────────────┬──────────┘
        │                           │
┌───────▼────────┐        ┌─────────▼──────────┐
│ واتساب Cloud   │        │ Google Calendar     │
│ API (تذكيرات)  │        │ + ICS للمريض        │
└────────────────┘        └────────────────────┘
```

- **الاستضافة:** VPS داخل مصر (أو خليجي قريب) — ٢ vCPU / 4GB تكفي بسهولة.
- **النسخ الاحتياطي:** يومي مشفّر، خارج نفس السيرفر، مع اختبار استرجاع شهري.
- **الأمان:** HTTPS إجباري، 2FA لحساب الإدارة، تحديث تلقائي، وتقييد الوصول لقاعدة البيانات.

## ٩. خطة التنفيذ

| المرحلة | المحتوى | المدة |
| --- | --- | --- |
| **١. الأساس** | تشغيل Easy!Appointments، إعداد الخدمات والأوقات، ضبط الحقول، تعريب كامل، ربط الدومين | ٢–٣ أيام |
| **٢. الواجهة** | تحويل البروتوتايب لواجهة إنتاج مربوطة بـ REST API + موافقة PDPL | ٤–٦ أيام |
| **٣. الواتساب** | قوالب Utility معتمدة (تأكيد/تذكير/إلغاء) + webhook عند الحجز | ٣–٤ أيام |
| **٤. التشغيل** | إدخال بيانات حقيقية، اختبار داخلي، تدريب الاستقبال، تشغيل متوازي مع الواتساب اليدوي | أسبوع |
| **٥. التحسين** | عربون، قائمة انتظار، تحليلات | لاحقًا |

**إجمالي المسار الحرج: ٣–٤ أسابيع** للوصول لتشغيل حقيقي.

### مؤشرات النجاح بعد ٦٠ يومًا

- ≥ ٤٠٪ من الحجوزات أونلاين بدون تدخل الاستقبال
- انخفاض الـ no-show ≥ ٣٠٪ مقارنة بالوضع الحالي
- متوسط زمن الحجز < ٩٠ ثانية
- صفر شكوى تتعلق بالخصوصية

## ١٠. البروتوتايب

في `clinic/prototype/` — واجهة حجز عربية كاملة وقابلة للضغط، بكل خصائص P0:

```bash
node clinic/prototype/server.js     # ثم افتح http://localhost:4173
```

الواجهة بتكلّم API بنفس شكل `Booking::register()` و`Booking::get_available_hours()` في
Easy!Appointments — يعني لما نربطها بالباك اند الحقيقي، التغيير في سطر واحد.
